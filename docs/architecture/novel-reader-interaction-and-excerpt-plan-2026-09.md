# 小说阅读器新增功能完善计划

日期：2026-09-07  
状态：待实施的设计与验收计划；本轮只新增本文档。  
范围：文本选择、划线与想法、笔记入口、书摘、字典、AI 问书、朗读及相关设置。

## 1. 目标与现状判断

目标是让“读到一句话 → 选择 → 记录/查询/分享 → 回到原文”形成稳定、精致的闭环。首先解决文本位置与手势归属，再完善视觉和功能边界。

本计划依据当前工作区代码和用户反馈。下面的实现缺口可以由源码确认；“闪出后消失”的具体事件顺序尚未完成设备复现，不将推断标记为已确认根因。

| 问题 | 当前实现证据 | 改进方向 |
| --- | --- | --- |
| 工具栏常出现在中间 | `calculateNovelSelectionToolbarOffset` 在 anchor 缺失时直接使用屏幕中心；`NovelSelectionContainer` 在选中文字为空时清空按下坐标 | 无有效几何信息时等待；禁止用屏幕中心掩盖定位失败 |
| 位置不随选区准确变化 | `selectionAnchor` 来自任意一次 pointer down；没有携带起止字符对应的实际矩形 | 以真实选区及排版结果生成锚定区域 |
| 已有划线的定位偏差 | `detectNovelMarkingTap` 将 Text 内的 `releasePosition` 直接传给根层浮层 | 全链路统一坐标系，并使用划线区域而非点击点 |
| 关闭时可能重现工具栏 | dismiss 只调用 `publishTextSelection(null)`；`selection.clear()` 未被调用；选区 effect 又依赖按下坐标 | 原子结束选区会话；旧回调不能恢复已关闭选区 |
| 多个文本容器竞争 | 各页/章节的空选区也会向共用状态发布 null；`publishTextSelection` 同时清除已选批注 | 带 owner/session 标识；仅当前 owner 可更新或清除会话 |
| 手势拦截不统一 | 全屏浮层、正文选区、已有划线命中、翻页、下拉书签均有 pointer 处理；普通文档路径只检查 `textSelection` | 明确每次手势唯一负责人，覆盖所有阅读路径 |
| 批注展示粗糙 | 想法只是工具栏 Column 里一段 `Text(maxLines = 4)` | 区分紧凑动作栏、想法预览卡、完整详情与编辑 |
| 主题缺少语义 | 六种模板共用大日期及相同内容顺序，差异主要是颜色、标签、引号与边框 | 每种模板定义独立信息层级、版式节奏与视觉语言 |
| 预览与导出不一致 | `NovelExcerptPreview` 使用 Compose Text，导出使用 Canvas/Paint 独立换行、独立装饰 | 一份文档、一份排版结果，预览与导出共享 |
| 字体差异不可信 | 当前书摘只映射系统 sans/serif/monospace/cursive；不同族的中文可能仍由同一字体回退 | 真实字体文件、明确加载状态、同一字体参与预览与导出 |
| 功能闭环不完整 | 笔记列表划线项没有正文跳转；字典 `awaitAll` 后才统一更新；AI 关闭时未取消本次请求；“听当前”实际只播选文 | 按功能补全入口、状态、返回与错误恢复 |

上一轮构建和纯逻辑测试通过，仅证明对应编译/规则检查通过。设备停在 Waiting For Debugger，不能算启动成功或 UI 验收。本轮也未做设备复现。

## 2. 文本选择与工具栏：先建立正确的位置模型

### 2.1 选区是范围，不是点击点

建议在现有小说模块内建立小型选区协调器，不把所有逻辑继续堆进 Activity。

会话至少包含：会话 ID、来源容器 ID、书籍/章节 ID、原文或译文身份、起止字符范围、文本快照、已有笔记 ID（可空）。当前屏幕上的几何信息由 UI 层持有，不持久化 LayoutCoordinates 或回调。

几何信息包含可见行矩形、可见选区边界、活动手柄位置、正文视口和安全区。统一转换到浮层所在根节点的坐标系；如果最终采用窗口 Popup，则整体统一到窗口坐标，不能混用。

复用 `TextLayoutResult` 的范围路径/字形信息计算选区形状；不能只凭 `indexOf(selectedText)` 找第一处文本。重复句子、段首缩进、空白规范化、跨段、分页截取和双语显示都要求维护“源范围 ↔ 渲染范围”的映射。官方 API 提供 [TextLayoutResult.getPathForRange](https://developer.android.com/reference/kotlin/androidx/compose/ui/text/TextLayoutResult)，但当前 SelectionState 可公开获取哪些锚点/范围，必须以项目实际依赖源码验证，不能预设内部 API 可用。

实施开始时做一个最小验证：能否通过当前 Foundation 的公开选区接口或工具栏回调取得可靠范围及边界，并保留原生手柄。仅有矩形的回调可用于定位，但不足以持久化准确范围。若公开接口不足，评估局部适配方案并记录代价，避免反射和复制整个选区引擎。

### 2.2 明确定位规则

1. 取当前可见选区的整体边界，以水平中心对齐工具栏；长选区不需要将屏幕外的全部行纳入边界。
2. 默认放在可见选区上方，间隔初值 8dp。上侧放不下完整工具栏时放下方。
3. 安全区扣除状态栏、导航栏、键盘和当前可见阅读控件。水平保留 12dp 边距；宽屏工具栏限制在当前文本栏的范围内。
4. 上下均放不下时先收起想法预览并将低频操作归入“更多”；仍不足时，在安全区内选择与选区/手柄重叠最少的位置，优先避开正在拖动的手柄。此时允许受限覆盖，但必须仍与可见选区相邻。
5. 拉动手柄、滚动、自动滚动、重排、旋转、分屏或 Insets 变化时重新计算。每帧合并位置更新，避免每一像素都触发业务状态发布。
6. 同一选区维持当前上下方向，只在空间不足时换边，并设小幅回切阈值，防止在临界位置跳来跳去。拖动期间不做滞后的弹簧追随动画。
7. 选区完全离屏或正在失效重排时暂时隐藏；几何恢复后按有效会话重新定位。无锚点时不显示在屏幕中间。

### 2.3 关闭、选择、翻页的时序

建议状态：空闲、选择中、拖动手柄、查看已有笔记、执行动作/编辑。浮层显隐从这些状态派生，不再分别维护互相矛盾的多组布尔值。

| 操作 | 预期结果 |
| --- | --- |
| 长按正文 | 开始新选区会话；手指未抬起前不触发阅读控件或书签手势 |
| 拖动选区手柄 | 只调整选区；工具栏按几何更新，不翻页，不下拉书签 |
| 点击当前浮层外的非手柄区域 | 只关闭当前会话；这一完整 down/up 不再派发给选区、翻页、划线命中或阅读工具栏 |
| 关闭后下一次独立点击 | 恢复普通阅读点击规则 |
| 空闲时点已有划线 | 按该条划线的可见矩形打开笔记浮层 |
| 浮层打开时点另一条划线 | 第一次只关闭；再次点击才打开另一条，避免一次手势同时关闭和打开 |
| 返回键 | 先退出编辑/详情，再退出选区，最后才退出阅读器 |
| 打开字典、书摘、AI 或编辑想法 | 冻结准确文本和来源快照，结束正文选区，再打开目标面板 |

结束会话必须同时使会话 ID 失效、清除 Compose 选区和手柄、清除 UI 记录。迟到的 selectedTexts 回调、离屏页的 null 和旧异步结果都不得恢复或覆盖新会话。事件消费与父处理器协作遵循 [Compose 手势分发文档](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/understand-gestures)；仅 consume 并不会自动停止所有处理器，所有候选处理器都要遵守归属与消费结果。

浮层不得以全屏不透明的命中层抢走手柄拖动。实施时验证正文根节点拦截、局部浮层和原生手柄窗口之间的事件路由。系统菜单禁用策略也应收敛为局部选区适配，评估替代当前进程级 Foundation flag 的方案并验证跨 Activity 恢复。

### 2.4 动作排列与样式

- 普通选文：划线、复制、写想法、书摘、AI 问书、听当前。字典和纯文本分享归入“更多”；窄屏保持前四项与“更多”可见，其余进入菜单。
- 已有划线：保持相同槽位，首项显示“已划线”状态，不点击即删除；“写想法”按内容改为“编辑想法”；追加独立“删除”。不再从首项移除划线导致整排按钮位移。
- 删除带想法的笔记时明确同时删除划线和想法，并提供撤销；清空想法文本保留划线。
- 不在选文动作中恢复“添加书签”；位置书签仍在阅读控件和下拉手势中操作。
- 采用紧凑文字/图标、圆角表面、轻阴影与细边界；与当前 Material/iOS 风格保持一致。触达区域至少 48dp，不靠强模糊解决视觉层级。

## 3. 批注与笔记：从操作栏中的文字升级为阅读卡片

产品术语统一为“划线、想法、书签”；“批注”对应附在划线上的想法。点评是整本书的记录，单独规划，不用空章节 ID 伪装成划线。

### 3.1 就地查看

点击划线后，动作栏与想法卡片构成同一个可定位的浮层组合：无想法时只显示动作栏；有想法时附带一张独立卡片。

卡片内容层级：顶部“我的想法”与编辑入口 → 想法正文 → 弱化的更新时间。通过左侧细线/小标记关联正文，避免大面积重复原文。正文初值 15–16sp、行高约 1.5 倍、16dp 内边距、16–20dp 圆角，最终通过设备截图调整。

短想法直接读完；长想法提供清楚的“展开”，进入可滚动的详情面板，不在小浮层里嵌套长滚动，也不无提示地截四行。屏幕空间不足时，优先保留紧凑动作栏和可展开的想法摘要。

详情面板展示完整原文引用、完整想法、章节与时间，支持编辑、书摘和定位原文。删除只占一个低强调入口。

### 3.2 编辑与列表

- 编辑器使用底部面板或宽屏侧面板：引用原文可折叠，正文输入有充足空间，保存动作固定可达，适配键盘；返回保留会话草稿，丢弃有明确入口。
- 保存中防重复提交，失败保留草稿并允许重试；同一已选范围写想法应更新已有笔记。
- 阅读菜单提供统一“笔记”入口，含全部、划线、想法、书签筛选。全部列表去重，想法是带内容的划线子集；明确计数规则。
- 按章节分组，支持按阅读顺序/更新时间排序与内容搜索；点击记录回到准确字符范围并短暂强调。
- 书签锚点不能只依赖旧页码；改变字号/方向/阅读模式后仍应回到原位置。停止借用 `imageUrl` 存储小说引用文本，评估兼容字段与迁移方案。
- 重复文本优先使用章节范围与上下文校验；找不到旧位置时显示定位状态，让用户重新关联，不能静默跳到同名句子的第一处。
- 点评列为后续阶段：复用已有书籍评论能力或新增明确的书籍级模型；在可保存、编辑和恢复前不展示空功能标签。

## 4. 书摘：六种主题各有表达目的

六种模板都保留完整选文、书籍信息和低强调的应用署名。日期在所有模板可用，但只有日历以日期为第一视觉中心。以下是 Kototoro 的设计提案，不声称复刻微信读书的内部设计规范。

| 模板 | 语义与阅读感受 | 版式与字体方向 | 背景与细节 | 长内容处理 |
| --- | --- | --- | --- | --- |
| 日历 | 把今天读到的一句保存下来 | 顶部大日、较小年月与星期；中部选文；底部书籍信息。日期用利落黑体，正文宋体 | 暖白日历纸、克制朱红强调、日历页分区；不添加无意义英文标签 | 日期区只在首张完整呈现；后续页缩为小日期，正文自然续接 |
| 经典 | 从一本书里取出的一页 | 书籍扉页/正文页的秩序；宋体、稳定版心、克制首字或段首处理；书名和作者以书籍署名方式收尾，日期退为页脚 | 象牙纸、深墨文字、细排版线；以字体比例和留白形成层级 | 最适合多段正文；增加页数而不是无限缩小字号 |
| 墨白 | 让文字本身成为主角 | 去除卡片内标签和大引号；严格网格、清晰黑白对比、宽留白；选文居视觉中心，来源小字对齐版心 | 黑与白两个受控版本；保留最少装饰；避免背景色破坏黑白语义 | 按篇幅调整留白，长文采用有序的整洁版心 |
| 静影 | 安静、停顿和空间感 | 偏置构图、较窄文字栏、舒缓行距；文字从光影中浮现；来源与日期放在平衡位置 | 低饱和灰蓝/炭灰，柔和渐变与确定性的斜光/窗影；阴影不得压过文字 | 减少大空白、延续光影方向，优先保证文字对比与可读性 |
| 手札 | 记录我读到这里时的感受 | 原文以引文块呈现，想法作为独立手写段落；文楷与正文区分；日期/时间如记录时间 | 温暖笔记纸、淡横线或点阵；行线由真实基线对齐；不将所有字体强制变成手写体 | 想法和引用各自自然续排；无想法时呈现摘录页，不显示假想法占位 |
| 锦书 | 值得珍藏、寄给某人的文字 | 精致书笺比例；中文书名、作者与日期形成落款；优先真实宋体，细致字距；可选用户主动填写题赠 | 绢纸/米金/黛青等受控配色，双层细框、抽象织纹；不虚构印章、作者签名或寄语 | 随内容延展书笺，极长内容拆为编号续笺，边框和落款保持秩序 |

验收不能只看模板按钮的名称：先隐藏模板名和颜色，用同一段文字比较六张灰度缩略图，仍应通过版式辨认；再评估色彩与纹理是否加强对应语义。

### 4.1 真正统一预览与导出

以 `ExcerptDocument → TemplateLayout → Render` 为单一链路。文档包含选文、可选想法、书名/作者/章节、日期、署名以及字体和主题配置；缺失作者不伪造，不依赖网络补全才能导出。

排版结果包含文字行、字体文件身份、坐标、装饰区域、尺寸与分页。预览展示同一结果的缩放版本，导出仅改变输出分辨率，禁止两套独立换行与截断规则。可选择共用绘制器或共享完整排版模型，具体实现通过首个模板验证性能与一致性。

默认“适合屏幕”查看完整卡片，并支持放大/滚动看长文细节。设置面板与保存/分享动作固定可达，不让用户必须滚完整个长书摘才能操作。

长内容默认自动增高；超过明确的像素/内存预算时转为多张卡片，并在预览显示张数。预检宽×高×像素格式的内存，逐张生成；绝不依赖无上限 Bitmap 高度。保留段落、空行、标点和 emoji；来源与想法不能与正文重叠。

相册保存纳入 API 26–28 权限路径检查、API 29+ pending 写入、失败记录回收；分享使用临时 URI，支持多图且清理过期缓存。快速切换配置取消过期渲染，防止旧主题结果覆盖新主题。

### 4.2 字体与主题选项

项目已有 `OnlineFontLoader`，并配置思源宋体、霞鹜文楷、Noto Sans CJK 等真实文件下载及摘要校验，应复用这条能力。书摘预览和导出消费同一已解析字体资产；仅有 Compose FontFamily 不足以保证 Canvas 输出一致。

首批建议：系统默认、思源宋体、霞鹜文楷、Noto Sans CJK。正式提供前核对字体项目许可和分发方式；下载中、成功、失败、离线可用状态明确。未加载成功时显示实际回退字体，保存时给出与预览一致的处理，不挂真实字体名称却静默使用系统体。

兰亭黑、仓耳系列、方正悠宋、京华老宋体、AI 楷等，只有取得可使用的实际文件并验证渲染后才纳入。当前不承诺这几个名称都能提供。

每个模板提供经过对比度检查的背景组合；切换模板首次采用自身默认配色/字体，保留各模板上次选择。明确区分推荐配色和自定义颜色，墨白等主题避免任意颜色使语义失效。首次下载才请求字体，不为全部模板预加载所有字体。

## 5. 新增功能的整体完善

| 能力 | 本轮应补齐的闭环 | 验收关注点 |
| --- | --- | --- |
| 章节标题置底 | 阅读内设置与“设置 → 阅读 → 小说”一致；审查旧偏好迁移、监听和保存覆盖；复用单一配置语义 | 首次升级、修改其他选项、重启与旋转后不反转；上下标题不重复；普通阅读与控件展开均有明确规则 |
| 字典查询 | 正文就近进入查询面板；默认源优先，每个源独立更新，失败可重试；管理入口保留 | 慢源不拖住快源，返回阅读位置不变；无启用源、离线、规则失败有完整状态 |
| Legado 对齐 | 以同级参考仓库整理规则字段、`{{key}}`、请求/提取语法、导入导出、默认源、排序启用、结果导航的逐项矩阵 | 每项标明已实现、部分支持或缺失，并有代表性规则用例；不能将“有字典页面”视为全面对齐 |
| AI 翻译术语 | 查询字典与书籍翻译术语表分清用途；提供术语查看/编辑，保护用户修订；检查缓存失效和作用域 | 人名跨章一致；改术语后的译文更新有明确策略；不同书籍不串数据 |
| AI 问书 | 选文、章节和问题组成不可变请求快照；关闭/新请求取消旧任务；支持复制、重试，明确服务未配置状态 | 连续问两段文本时旧结果不能串入；只发送所需上下文；说明回答依据是选文/局部上下文，避免暗示已理解全书 |
| 听当前 | 默认定义为“从选区起点连续朗读”，另提供“只听选文”；复用已有 TTS 会话而非孤立片段 | 起始位置正确、暂停恢复、跨页/章、原译文选择及高亮正确；服务未就绪时能等待或重试 |
| 备份与同步 | 核查划线、想法、书签、术语表和字体配置是否进入当前备份/同步序列化路径 | 当前定向检索未发现小说标记/术语专用接入，需进一步追踪通用路径；只有做过备份恢复往返测试才声明支持 |
| 无障碍与性能 | 字体缩放、TalkBack、RTL、双页、折叠/分屏、暗色及关闭动画模式 | 不因工具栏重测触发正文分页；拖动定位只更新必要 UI；低配设备长书摘有可控峰值内存 |

数据策略：先统一产品入口和领域语义，尽量复用现有仓库；不为了“笔记统一”立即把书签与划线强行合并为一张表。若确需迁移，先形成字段映射、旧数据兼容与备份方案，再按仓库规则执行迁移。

## 6. 实施阶段与交付门槛

| 阶段 | 内容 | 阶段交付与门槛 |
| --- | --- | --- |
| P0：稳定性基线 | 建立固定小说样本和真机复现；核实当前 Compose API；记录选区事件序列；统一会话、坐标、关闭逻辑和原文范围 | 短选区、跨段选区、已有批注均可稳定定位；拖柄跟随；关闭无闪回、无翻页/书签副作用；原生手柄正常且无系统第二工具栏 |
| P1：笔记体验 | 统一动作栏、想法卡片、详情/编辑面板、列表筛选、定位与撤销 | 短/长想法、无想法、编辑失败、旋转、字号变化、重复文本定位完整验证；先完成当前三类笔记，点评不阻塞本阶段 |
| P2：书摘排版基础 | 建立单一文档与排版结果、真实字体状态、长文/多图导出、固定操作区；先做日历和经典 | 同一配置的预览/相册/分享排版一致；文字完整；字体名与实际文件相符；限制内存且错误可恢复 |
| P3：主题设计 | 完成墨白、静影、手札、锦书；统一六套模板的视觉评审 | 同一短文、长文、带想法样本形成主题样张；灰度下结构仍有辨识度；所有配色、字体加载状态均可用 |
| P4：周边闭环 | 字典/AI/TTS、偏好迁移、备份同步、全路径无障碍与性能核查 | 补齐对齐矩阵；通过跨模式/生命周期回归；对未完成能力清楚标识，不以编译通过代替功能验证 |

P0 完成前不继续调整错误锚点上的动画；P2 的统一排版完成后再扩展剩余模板。每阶段按可运行结果验收，再进入下一阶段。当前不基于未复现的 UI 问题给出虚假精确工期。

## 7. 验证方案

固定样本含：重复句子、单字/单行、屏幕顶/底部多行选区、跨段/跨页、缩进与空白变化、中英混排、emoji、RTL、原文与译文；笔记覆盖空想法、短想法及长想法。书摘覆盖短句、约 300 字、约 1500 字和触发多卡片的大文本。

有意义的自动验证包括：

- 选区会话：旧回调/离屏容器不能清除或恢复当前会话；关闭时底层选区与 UI 同时退出。
- 几何：范围坐标转换、可见区裁剪、上下选择、边界夹取、换边阈值和双页限制。必须驱动真实计算函数，而非复制逻辑写测试。
- 集成手势：长按 → 拖柄 → 点外部；验证 toolbar 只关闭一次，翻页/阅读控件/书签回调均为零。连续重复并覆盖高刷新率设备；保留失败录屏与事件轨迹。
- 文本定位：同章重复句子、跨段、字号变化、译文切换后的范围身份正确；不可定位数据不得误关联。
- 书摘：共用排版结果的文本完整性、字体资产身份、分页和最大内存预算；截图对比配合人工视觉评审，不能只验证 template 枚举不同。
- 异步：查询慢源/失败源、AI 关闭后返回、TTS 未就绪、字体下载失败、相册写入失败和配置快速切换。
- 数据：升级兼容、笔记增改删、删除撤销、备份恢复往返。

构建入口沿用 `:app:compileDebugKotlin`、定向 `:app:testDebugUnitTest` 和需要时的 `:app:connectedDebugAndroidTest`。设备运行须确认已进入小说正文，不能停留在调试器等待状态。最终报告区分自动测试、实际设备已验证项目和剩余限制。

## 8. 代码落点与范围控制

以下路径均相对仓库根目录，作为实施导航：

- `app/src/main/kotlin/org/skepsun/kototoro/reader/novel/compose/NovelTextSelection.kt`：选区范围、来源、几何与已有划线命中。
- `app/src/main/kotlin/org/skepsun/kototoro/reader/novel/compose/ComposeNovelReader.kt`：正文路径、手势归属、浮层定位；拆出局部协调组件，避免继续膨胀。
- `app/src/main/kotlin/org/skepsun/kototoro/reader/novel/compose/NovelComposeReaderViewModel.kt`：单一活动会话与带来源的事件。
- `app/src/main/kotlin/org/skepsun/kototoro/reader/novel/compose/NovelTextSelectionActions.kt`、`ComposeNovelMarkingsSheet.kt`：统一动作与笔记卡片/列表。
- `app/src/main/kotlin/org/skepsun/kototoro/reader/novel/compose/NovelExcerpt.kt`：拆出文档、排版、模板和渲染职责，共享预览/导出结果。
- `app/src/main/kotlin/org/skepsun/kototoro/reader/novel/NovelReaderActivity.kt`：动作路由与现有服务连接；请求生命周期逐步交由明确的状态所有者管理。
- `app/src/main/kotlin/org/skepsun/kototoro/core/ui/theme/OnlineFontLoader.kt`：复用真实字体资产与下载状态。
- `app/src/main/kotlin/org/skepsun/kototoro/dictionary/`、`core/dictionary/`：规则对齐、查询状态与翻译术语。
- `docs/development/compose-novel-reader-parity-matrix.md`：实施后更新功能等价与验收状态。

遵循 KISS/DRY：以一个选区会话、一套坐标约定、一份书摘排版结果收敛重复实现；按职责拆分而不创建通用插件框架。遵循 YAGNI：优先完成用户已有流程；点评、可下载模板市场和复杂自定义编辑器不进入前置阶段。所有新增能力延续现有主题、资源本地化、服务与仓库，优先不增加依赖。
